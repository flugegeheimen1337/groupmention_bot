# Упоминания в Telegram

Сервис смотрит группы и супергруппы аккаунта и присылает в отдельного бота сообщения, где этот аккаунт отметили. Обычный ответ без тега не пересылается. История до запуска не читается.

Нужны свои `api_id` и `api_hash` с [my.telegram.org](https://my.telegram.org) и токен бота от [@BotFather](https://t.me/BotFather). Бот в группы добавлять не нужно.

## Настройка

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
```

В `.env` заполните `API_ID`, `API_HASH`, `BOT_TOKEN`, `PHONE` и `EXPECTED_USERNAME`. Файл `.env` и файл сессии в git не коммитятся. `EXPECTED_USERNAME` — username аккаунта без `@`. После входа программа сверяет его и не запускает слежение для другого номера.

Первый вход интерактивный. Код приходит в служебный чат Telegram того номера, который указан в `PHONE`. Если включена двухэтапная проверка, программа спросит пароль в терминале.

```bash
.venv/bin/python -m app.login
```

После входа откройте бота с этого же аккаунта и нажмите «Запустить». Затем запустите слежение:

```bash
.venv/bin/python -m app
```

Проверка: с другого аккаунта отправьте в свою группу `@username`. В бот приходят название группы, автор, текст и кнопка «Перейти к сообщению». Повтор того же сообщения не приходит. В обычной старой группе кнопки может не быть: у такого чата нет прямой ссылки на сообщение.

## Сервер

Каталог сервиса — `/opt/groupmention`. Туда копируются код, `.venv` и `.env`. Сессия создаётся командой `python -m app.login` уже на сервере.

```bash
sudo cp deploy/groupmention.service /etc/systemd/system/groupmention.service
sudo systemctl daemon-reload
sudo systemctl enable --now groupmention
```

Новый сеанс виден в Telegram: «Настройки → Устройства». Его нельзя завершать, иначе вход придётся повторить.
